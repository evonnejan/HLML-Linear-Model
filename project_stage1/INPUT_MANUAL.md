# HL01 預測 Input 準備手冊

## 0. 手冊目的與最終輸入

本手冊說明如何把原始紀錄整理成模型的輸入。

最終輸入是一張 60 列的表：

- 每分鐘一列，時間從 t−59 到 t（包含 t）。t 是最後一列的時間，也就是預測起點；模型會預測 t+1 到 t+15 的 HL01。
- 欄位依序如下，共 15 欄：

```text
date, HL01, HL02, HL03, HL04, HL05, HL06,
Past10Min, Past1Hr,
north_gate_opening_1, north_gate_opening_2, north_gate_opening_3,
south_gate_opening_1, south_gate_opening_2, south_gate_opening_3
```

- HL01 不是模型特徵，只會用到最後一列，作為預測的起點。因此最後一列的 HL01 必須是實測值，不能是沿用來的值（判斷方式見 4.3）。
- 時間一律是台灣時間（UTC+8），照資料庫裡的時間寫，格式為 `YYYY-MM-DD HH:MM:SS`，例如 `2026-10-01 12:00:00`。

## 2. 時間對齊

以水位的每分鐘為時間軸，把所有欄位對齊到整分鐘。

- 時間軸是連續的整分鐘，每分鐘一列。某一分鐘水位剛好沒有資料，也要建立這一列，第 3 節會補值。
- 水位：取 measure_time 等於這一分鐘的紀錄；沒有就留空。
- 雨量、閘門：往前找最近的一筆，時間要小於或等於這一分鐘，不能用這一分鐘之後的紀錄。
  - 12:02:30 的紀錄從 12:03 起才用得到，不能算到 12:02。
  - 12:00 的雨量一路用到 12:09，12:10 起改用 12:10 的紀錄。
- 閘門同一分鐘內有多筆紀錄時，以最後一筆數字為準；如果都不是數字，就依第 3 節沿用前一分鐘的值。
- 往前找要找到有紀錄為止，不能只在最新一批入庫的資料裡找。閘門只在開度改變時回報，可能好幾天才有一筆，這段期間的開度就是最後一筆紀錄的值。
- 雨量、閘門在兩筆紀錄之間沿用前一筆，是正常的對齊，不算修改，不用記入修改紀錄表。
- 對齊時照搬原值，文字也照搬，先不要轉成數字。先轉成數字的話，T、X 這類代碼會變成空值，第 3 節就無法辨識。

## 3. 特殊碼與遺失值處理

### 3.1 處理規則

對齊後，每一格依下表處理。每欄各自處理；「沿用」是指沿用這一欄前一分鐘處理後的值。

| 資料 | 對齊後的原值 | 處理方式 |
|---|---|---|
| 水位 | ≥ 0 的數值 | 直接使用 |
| 水位 | 負值 | 沿用 |
| 水位 | 其他（無資料、空值、文字） | 沿用 |
| 雨量 | ≥ 0 的數值 | 直接使用 |
| 雨量 | -98（連續 6 小時無降水）、T（雨跡） | 改成 0.0 |
| 雨量 | 其他（X、-99、空值、其他負數、文字） | 沿用 |
| 閘門 | ≥ 0 的數值 | 直接使用 |
| 閘門 | 負值 | 改成 0 |
| 閘門 | 其他（空值、文字） | 沿用 |

- -98、-99 不論存成數字或文字都要認得；文字比對前先去掉前後空白。
- 閘門負值代表閘門持續往下關閉，不具物理意義，一律當作 0。

### 3.2 修改紀錄表

只要某一格不是直接使用原值（改成 0.0、改成 0 或沿用），就在修改紀錄表 `hl01_change_log` 記一筆：

| date | column_name | raw_value | new_value |
|---|---|---|---|
| 2026-10-01 12:10:00 | Past10Min | -98 | 0.0 |
| 2026-10-01 12:15:00 | HL03 | NO_RECORD | 164.0 |

- `date`：這一格所在的分鐘。
- `column_name`：這一格的欄位名稱。
- `raw_value`：對齊後的原值，以文字儲存；水位該分鐘沒有紀錄時寫 `NO_RECORD`。
- `new_value`：處理後的值。

### 3.3 例子

north_gate_opening_1 的原始紀錄：11:58:40 為 1.80、12:01:10 為 NULL、12:02:30 為 1.85、12:03:20 為 ERR、12:05:00 為 1.90。

| 分鐘 | 對齊後的原值 | 處理後 | 修改紀錄 |
|---|---|---|---|
| 12:00 | 1.80（11:58:40） | 1.80 | — |
| 12:01 | 1.80（11:58:40） | 1.80 | — |
| 12:02 | NULL（12:01:10） | 1.80 | NULL → 1.80 |
| 12:03 | 1.85（12:02:30） | 1.85 | — |
| 12:04 | ERR（12:03:20） | 1.85 | ERR → 1.85 |
| 12:05 | 1.90（12:05:00） | 1.90 | — |

## 4. 存表與取 input

目前的想法是在資料庫建立 4.1 的兩張表，把處理好的資料存進去；每次要預測時，再從分鐘表取出 60 列作為 input。實際做法可依你們的系統調整，只要最後交給推論程式的 60 列符合第 0 節的格式即可。

### 4.1 建立分鐘表與修改紀錄表

| 建議表名 | 欄位 | 用途 |
|---|---|---|
| `hl01_minute`（分鐘表） | 第 0 節的 15 欄 | input 從這裡取 |
| `hl01_change_log`（修改紀錄表） | `date`、`column_name`、`raw_value`、`new_value`（見 3.2） | 追溯哪些格子不是原值；判斷 HL01(t) 是不是實測 |

- 表名只是建議，可依你們的命名習慣自行決定；本手冊以下都用這兩個名稱說明。
- 每批資料處理完，先做 4.2 的檢查，再把通過的列寫入兩張表，接在最後面。

### 4.2 寫入前檢查

每一批處理好的新資料，寫入分鐘表之前逐列檢查：

| 檢查項目 | 標準 |
|---|---|
| 欄位 | 剛好是第 0 節的 15 欄 |
| 時間 | 格式為 `YYYY-MM-DD HH:MM:SS`、落在整分鐘；由舊到新、每列相隔 1 分鐘；第一列接在分鐘表最後一列的下一分鐘（第一次建表除外） |
| 數值 | date 以外的 14 欄都是數字，沒有空值或無限大 |
| 負數 | 水位、雨量、閘門都沒有負數 |

- 全部通過：整批寫入兩張表。
- 有一列沒通過：這一列之前的列照常寫入兩張表；從這一列開始先不寫入。這一列修正後，再從它開始接著寫入。

### 4.3 取 input

- 要預測 t+1 到 t+15，就從 `hl01_minute` 取 t−59 到 t 共 60 列，這 60 列就是 input。不需要準備 t 之後的資料。
- t 通常是 `hl01_minute` 最新的一分鐘。HL01 在 t 必須是實測值，也就是 `hl01_change_log` 裡沒有 `date` 為 t、`column_name` 為 HL01 的紀錄。

### 4.4 不能預測的情況

- 有一列沒有通過寫入前檢查：分鐘表會停在這一列的前一分鐘，t 最晚只能到那一分鐘；這一列修正並寫入後，才能繼續往後預測。
- HL01 在 t 不是實測值：這一輪不預測，等下一輪。
- 推論程式在預測前還會自動檢查一次這 60 列；沒有通過就不預測，並回傳原因。

### 4.5 寫入資料庫的時段

寫入資料庫會佔用資料庫的資源。如果上班時間大家都頻繁使用資料庫，可以考慮：

- 大量寫入（例如第一次用歷史資料建表、回補或重算一段期間）排到晚上等離峰時段進行。
- 如果資料庫忙到查詢常常要等，可以考慮白天把分鐘表放在本機（例如 CSV），預測時從本機取 60 列，晚上再同步進資料庫。修改紀錄表和推論程式的預測結果表也可以用同樣的方式處理。
- 改放在本機時，4.2 的檢查和 4.3 的取法不變，只是對象從資料庫換成本機的檔案。

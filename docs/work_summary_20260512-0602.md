## 1. `water_level_rain_gate_all.csv` 怎麼來的 + DLinearMix2 架構

```

   │    (RAIN_THRESHOLD=0.1, gap=30min,      │ filter_wra_cogate_columns.py
   │     min_seg=60min, pre/post=60min)      │  - 取 7 個開度欄、改英文名
   │  - 標 isRain / segment_id /             │  → wra_cogate_obs_wide_gate_opening.csv
   │    SegmentStart/End / WinStart/End      │
   ▼                                         ▼
water_level_rain_all4.csv  ──────┐   ┌────  (gate 寬表)
                                 ▼   ▼
                         merge_gate_data.py
                          - merge_asof(backward), 5min staleness → 過期設 NaN
                          - 負值 clip 0；每個 segment_id 內 ffill
                          - 丟常數欄 (StationId)

                    dataset/water_level_rain_gate_all.csv   ← 訓練資料
```

欄位構成：水位 `HL01`–`HL06`、降雨 `Past10Min/Past1Hr/Now`、`isRain`、7 個 gate 開度、segment metadata。

### 1b. DLinearMix2 架構（`models/DLinearMix2.py`）

輸入張量約定 channel 順序為 `input_cols + exog_cols`（由 Data_Loader 保證）：

```
x [B, L, C]
 ├─ 前 branch_in 個 channel  → 每個序列各一個 DLinear branch
 │     (series_decomp → trend/seasonal 各一條 Linear → [B, P, 1])
 │     branch_preds: [B, P, K]
 │
 └─ 後 exog_in 個 channel    → GRU ExogenousEncoder
        (逐步讀外生序列，取最後 hidden → context embedding [B, exog_emb_dim])

 融合 (兩種模式):
   flatten_fusion=True : flatten branch_preds [B, P*K] ⊕ exog_emb → 大 MLP → [B, P, 1]
   flatten_fusion=False: 每個 horizon 共享 MLP，輸入 [branch_preds ⊕ broadcast(exog_emb)]
                                                                      → [B, P, 1]
```

設計理念：把降雨/閘門當作**情境(context)**用 GRU 編碼，而不是硬塞成跟目標一樣的序列；各上游水位用獨立 DLinear 分支抓趨勢，最後融合預測目標站。
評估 run 的設定：`seq_len=60, pred_len=15, kernel=25, flatten_fusion=True, exog_emb_dim=16, fusion_hidden=32`，**約 17,357 參數**。

## 2. 用 DLinearMix2 做了哪些嘗試？結果如何？

`runs/DLinearMix2/DLinearMix2_summary.csv` 共 **57 個 run**，分三類：

| 類別 | 輸入 | run 數 | 用意 |
|------|------|--------|------|
| **HL01-in**（5/18） | `HL01,…,HL06` | 10 | sanity：輸入含目標站本身 |
| **no-HL01**（5/18–19） | `HL02–HL06` | 45 | 真正的題目：**不看 HL01，用上游站跨站預測 HL01** |
| **HL03-in**（5/20） | `HL03–HL06`（再丟 HL02） | 2 | 變體 |

掃的維度：`seq_len ∈ {30,45,60}` × `flatten_fusion ∈ {T,F}` × `criterion ∈ {mse, huber β0.5, huber β1.0}`，dual checkpoint（best-by-MSE / best-by-Corr），seed=42。

**結果（重點，皆為 test set = 颱風季）：**

- **HL01-in** 很容易：MSE 低到 1,164–6,329、Corr ≈ 0.99（因為輸入已含目標站歷史，接近 persistence）。
- **no-HL01** 是困難題：MSE 落在 ~20,000–48,000、Corr ≈ 0.70–0.83。
  - 最佳（最低 MSE）：`sl60 + flatten + huber β1.0 + best_mse` → **MSE ≈ 20,884、Corr 0.83→0.80（h1→h15）** → 就是現在的評估 run。
  - 大方向：**flatten_fusion=True、seq_len 越長、Huber loss** 通常較好。

⚠️ **重要 caveat**：所有 no-HL01 run 的 `improve_MSE_pct` 都是大負值（約 −760% ~ −2000%），表示 MSE 上**贏不過 persistence**。但這不是公平對打 —— persistence 需要「看得到 HL01 現值」，而模型被刻意**不給** HL01。所以 persistence 是一個很強的參考線（HL01 自相關高），不是模型能對等比較的對象。模型的價值在於 **Corr 高（抓得到動態/時序形狀）但 MSE 大（絕對水位有偏移）**。

## 3. Persistence baseline 是什麼？怎麼做？可以看什麼？

**定義**：最笨的預測 —— 「未來 = 現在」，即 `ŷ(t+k) = HL01(t)`（最後一個輸入時刻的目標值，對所有 horizon 重複）。實作在 `exp_Main2.py` 推論迴圈裡，需 `label_len ≥ 1`，與模型輸出同 shape 同順序，方便逐 horizon 對照。

**可以看的指標**（summary 與 outputs 都有）：
- `persist_MSE / persist_MAE / persist_corr_mean`
- `improve_MSE_pct = (persist − model)/persist × 100`（正 = 模型贏）、`improve_MAE_pct`
- `improve_h1_MSE_pct`（t+1）、`improve_hN_MSE_pct`（t+15）
- 圖：`outputs/persistence_improve.png`、表：`outputs/persistence_metrics.csv`

**為什麼有用**：水位是慢變、強自相關的訊號，**短 horizon 的 persistence 幾乎完美**（評估 run 在 h1 是 −29,641%，到 h15 收斂到 −268%）。所以它是檢驗「模型到底有沒有學到東西、在哪個 horizon 才開始有價值」的底線。

## 4. 為什麼要用 `Data_From_SQL_all.py` 抓 `all_minute_wide.csv` 跟 `rain_segments_meta.csv`？

訓練資料 `water_level_rain_gate_all.csv` **只包含降雨 segment（+前後 60 分鐘 window）**，沒有「乾燥期」的資料。要做乾燥段評估就需要**完整連續時間軸**。

`Data_From_SQL_all.py` 重用 Data_From_SQL_4/5 的同一套 SQL 與前處理，但**不做 segment 過濾**，產出：
- **`all_minute_wide.csv`**：全期間 1 分鐘連續寬表（water+rain+gate），共 **511,679 列，2024-08-13 ~ 2025-08-03**。供 eval_dry 切出乾燥段。
- **`rain_segments_meta.csv`**：**159 個降雨 segment** + window + **train/val/test split 標籤**（70/10/rest，依 SegmentStart 排序，與 Data_Loader 切法一致）。供 eval_dry 標記「哪些分鐘屬於降雨 window」。

一句話：**訓練資料是「事件切片」，eval 需要「整條連續時間軸 + 事件邊界」，所以另外抓。**

## 5. `eval_dry.py` 要做什麼？（任務目標）

**目標**：把在「降雨事件」上訓練的模型，丟到**完全沒下雨的乾燥期**測它的表現 —— 檢查它在平靜狀態會不會亂噴、能不能贏過 persistence、退水動態抓得如何（呼應 5/20「拿沒降雨的 segment 去 test」）。

**怎麼做**：載入已訓練 checkpoint → 從訓練 CSV 重新 fit scaler → 在 `all_minute_wide` 上標記每分鐘距上次降雨多久 → 找連續 ≥180 分鐘的乾燥段 → 切 sliding window → 依距上次降雨分**兩組**（`post_rain` 0–180min、`pure_dry` >180min）→ 逐 (組×horizon×segment) 算 MSE/MAE/RMSE/Corr，並對照 persistence。

**產出**：`dry_metrics.csv`、`per_horizon.csv`、`per_segment.csv`、`predictions.npz`、fanplot/box/time-series 等圖；best_mse 與 best_corr 兩個 checkpoint 各一份。

## 6. 最後做出什麼（評估 run + eval_dry，重點 best_mse）

**評估 run**：`...-to-HL01_sl60_pl15_st1-1_20260519-175611`
（no-HL01、sl60、flatten=True、Huber β1.0、early_stop=mse、seed42、17,357 params）

### 6a. Test set（降雨事件，best_mse / primary checkpoint）
- 逐 horizon MSE ≈ 19,880–22,791，**Corr 0.83 (h1) → 0.80 (h15)**
- vs persistence：`persist_MSE ≈ 2,430`、`improve_MSE_pct ≈ −759%`（MSE 贏不過，但 Corr 高）

### 6b. 乾燥段評估（`eval_dry/best_mse/`）
資料：dry_segment 106 段、建出 **439,122 windows**（pure_dry 433,618 / post_rain 5,504）。

| group | n_windows | MSE | RMSE | MAE | Corr | persist_MSE | improve_MSE% |
|-------|-----------|-----|------|-----|------|-------------|--------------|
| **pure_dry** | 433,618 | 6,853.6 | 82.79 | 53.76 | **0.431** | 307.1 | **−2,132%** |
| **post_rain** | 5,504 | 10,655.7 | 103.23 | 60.48 | **0.793** | 249.4 | **−4,173%** |
| all | 439,122 | 6,901.3 | 83.07 | 53.84 | 0.451 | 306.3 | −2,153% |

**逐 horizon**（best_mse）：improve_MSE% 由 h1 往 h15 收斂（pure_dry −3,258%→−1,774%；post_rain −6,057%→−3,375%），同樣是 persistence 在短 horizon 壓倒性強。

**怎麼讀這個結果（誠實版）**：
- 乾燥期水位幾乎不動，persistence「維持現值」近乎完美 → 模型 MSE 遠大於它（−2000% 等級）。
- 但 **post_rain 的 Corr 0.79** 明顯高於 pure_dry 的 0.43 → 退水動態模型抓得到形狀，只是絕對水位有偏移（高 MSE、低 improve）。
- 與 §2 的 caveat 一致：no-HL01 模型看不到 HL01，能對齊**動態**但對不準**絕對水位**。

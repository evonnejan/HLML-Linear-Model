降雨事件定義對照：Past1Hr（現行）vs Past10Min（官方建議）

目的：檢視現行訓練資料的降雨事件定義，與氣象署建議的量測慣例之間的落差，並評估若改用官方定義（Past10Min）對資料量的影響，供討論「要不要換定義」。

資料：dataset/all_minute_wide.csv（全期間連續分鐘表，511,679 min，2024-08-13 ~ 2025-08-03） 切分邏輯：忠實複刻 Data_From_SQL_4.py 的 segment_intervals()。

1. 官方（氣象署）對雨量量測的說明（重點）

  • 雨量儀為傾斗式，最小解析度 0.5 mm；每筆數值是「前次觸發到本次觸發之間」的累積量。
  • 判斷「當下是否降雨」建議用 過去 10 分鐘累積降水量（Past10Min），最即時。
  • 有效降雨門檻 = 大於 0.5 mm；低於此值可能為儀器誤差或微量降雨（未達翻轉門檻）。
  • 降雨事件開始 = 首次 Past10Min > 0.5 mm。
  • 降雨事件結束 / 中斷無統一標準，需依應用（防汛/農業/水文）自訂，通常會再參考雷達回波等資料綜合研判。
  • 缺值會標「累積於後」（缺漏期間雨量灌到下一筆），建議比對鄰站或雷達，避免誤判事件時長。
  • 目前無對外的降雨事件判定技術規範；雨量觀測可參考「地面氣象測報作業規範」。

2. 一個關鍵資料事實：雨量值是 0.5 的倍數

實際檢查 Past10Min / Past1Hr / Now：全部都是 0.5 的倍數，最小非零值 = 0.5 mm，與傾斗解析度吻合。

推論：

  • 現行門檻 >= 0.1 在這份量化資料上等同 >= 0.5（最小一斗就是 0.5）→ 所以本文兩種定義都用 >= 0.5，數字概念不變。
  • 官方「有效降雨 > 0.5」嚴格說是 ≥ 1.0（≥ 兩斗），比現行「≥ 一斗」略嚴；差別在是否收進「單斗微量雨」。本文沿用「≥ 0.5（至少一斗）」以對齊現行行為，聚焦在判定欄位（Past1Hr vs Past10Min）這個實質差異。

3. 現行定義

參數值作用
判定欄位Past1Hr（過去 1 小時累積，mm）「有雨」依據
門檻>= 0.1（≡ >= 0.5）該分鐘是否算有雨
gap30 min相鄰有雨點間隔 > 30 分 → 切成新事件
min_dur60 min事件跨度（首到末有雨點）< 60 分 → 丟棄（且有雨點數 > 1）
pre/post window60 / 60 min事件前後各補 60 分鐘做 context（isRain=0）

「可橋接的停雨空檔」：因為門檻欄位是累積量，雨停後仍會 ≥ 門檻一段時間，把短暫停雨「填平」、不切事件。

  • Past1Hr：雨停後 ~60 min 才歸零 + gap 30 → 可橋接 ~90 min 的真實停雨。
  • Past10Min：雨停後 ~10 min 歸零 + gap 30 → 只能橋接 ~40 min。

例 B 續 — 推薦設定怎麼補救（gap=45）

把 Past10Min 的 gap 從 30 放寬到 45：

21:50 之後幾個 burst 之間的空檔都 < 45，被併成一個乾淨的 119 分鐘事件，救回原本被當碎片丟掉的那段；而 21:00–21:50 的 50 分鐘大空檔仍 > 45，維持與前段分開 —— 這是對的，那本來就是兩波雨。→ 這就是為什麼推薦 gap≈45：補救碎裂，又不會把真正分開的兩波雨亂併。

解讀

  1. 碎裂確實發生：Past10Min 候選 +64%（沒有 60 分記憶橋接，對流雨一陣陣被切開）。
  2. 但碎片大多活不下來：78% 候選被 60 分門檻濾掉 → 保留事件反而 156→86（−45%）。
  3. 標記雨量縮水近 6 成：差的那一半主要是 Past1Hr「已停雨但 1 小時內下過」的尾巴 → 現行 isRain 約灌水 2.4 倍。

兩個旋鈕方向相反（依 regime）

  • min_dur 低（30）：短暴雨本來就活著，加 gap 只是把它們合併 → 事件數隨 gap 下降（145→126）。
  • min_dur 高（60）：事件稀少，靠 gap 接長才過關 → 事件數隨 gap 上升（86→112）。
  • 涵蓋分鐘：隨 gap 升、隨 min_dur 降；grid 內最高 gap90/min30 = 4.9%，仍到不了 6.4%（缺的是假尾巴）。

8. 結論與建議

核心結論：Past1Hr 的 60 分鐘累積尾巴同時灌大了「事件數」與「涵蓋時間」，Past10Min 兩者都缺；調 gap 能補回「橋接」、調 min_dur 能補回「短事件」，但無法同時追平兩者——剩下的差距就是被移除的「已停雨尾巴」。

目標建議組合結果
最貼官方（橋接最少）gap=30, min=30145 事件 / 3.0%
事件數≈現行 + 適度橋接（推薦）gap=45, min=30144 事件 / 3.8%
訓練資料量最大化gap=90, min=30126 事件 / 4.9%

推薦 gap=45 / min_dur=30：事件數幾乎追平現行（144 vs 156），gap 僅溫和橋接、不亂併獨立暴雨；涵蓋少掉的部分正是被砍掉的「已停雨尾巴」，對「官方定義的正在下雨」反而更誠實。

取捨提醒（給討論用）

  • 維持 Past1Hr：水文上站得住腳（水位對累積雨量有遲滯反應，尾巴是有用訊號），資料量足；但須在報告中明講 isRain 是累積量定義、比官方「正在下雨」寬。
  • 改用 Past10Min：貼合官方慣例、邊界更乾淨；但資料量明顯縮水，且換定義後 segment / train-test split / 所有 MSE-Corr 全數改變，與現行結果不可直接比較。

# 00 — 研究問題與目標

> **本檔是「受審宣稱」（Tier 1），不是事實。** 與程式碼／資料不符即為 finding。

## 1. 研究問題

以**上游鄰站水位 + 降雨 + 閘門開度**，預測目標站 **HL01 未來 15 分鐘**的水位。

- 時間解析度：1 分鐘
- 輸入窗長 `seq_len`：實務用 96 分鐘（`run.py` 預設值為 60，非實驗設定）
- 預測長度 `pred_len`：15 分鐘
- 目標欄：`HL01`
- 輸入欄：`HL02`–`HL06`（鄰站水位）
- 外生欄：降雨（`Past10Min` / `Past1Hr` / `Now`）、退水時間（`min_since_rain`）、閘門開度（7 欄）

## 2. 系統定位（2026-09-02 定案）

**即時預警系統（real-time warning）。** 虛擬水位量測是更長遠的目標。

這個定位有實質後果：即時預警在推論時**有 HL01 的當下感測讀數**可以當錨，
因此 roadmap #1 的 delta-target（預測「相對最後觀測值的變化量」）可行。
若日後轉向虛擬水位量測（該點根本沒有感測器），此路不通，roadmap #1/#4 需重新設計。

出處：`meeting_recap.txt` 5/20「(即時預警系統可用 / 虛擬水位量測不可用)」。

## 3. 兩條建模原則

1. **不放 HL01 自身歷史當 input。** 試過會造成自迴歸過度依賴。
   用 HL01 **最後一個觀測值**當外部錨（後處理或 delta-target）則可以。
2. **主指標看 correlation。** 絕對 level 可以事後校正，**變化形式**才是要學的東西。

> ⚠️ 原則 1 目前**在程式層面沒有任何強制機制**，且現行 sweep 腳本實際違反了它。
> 見 `05-traceability.md` T-01 與 `06-open-issues.md` OI-01。

## 4. 成功判準

| 項目 | 目前狀態 |
|---|---|
| 主指標 | mean per-horizon Pearson correlation（跨 window pooled） |
| 必須打敗的 baseline | **persistence**（predict `t+k = t`） |
| 數字門檻 | **無。尚未訂定。** |
| 次要指標 | MSE / MAE、per-horizon 分解、per-segment 分解、anchored 版本 |

**這是一個已知缺口。** 目前沒有「corr 要到多少」「比 persistence 好多少個百分點才算成功」
「預警要提前幾分鐘、允許多少誤報」的成文標準。
**請審查者評估這個缺口在論文層級的嚴重性，並建議該怎麼訂。**

## 5. 明確的非目標

- 不做多站同時預測（單一目標站 HL01）
- 不做 15 分鐘以上的長期預報
- 目前不做虛擬水位量測（列為長遠目標，見 §2）
- 不做流量／洪水淹沒範圍推估
